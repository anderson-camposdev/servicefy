Fontes, tamanhos e cor — o que o código realmente está renderizando

Boa notícia: a fundação existe e é madura (escala tipográfica completa, motor white-label, paleta de status). O problema do "sem graça" não é falta de sistema — é que peças do sistema não estão conectadas. Abaixo, o que encontrei nos arquivos e como ligar os fios.

00 Resumo dos achados
Crítico
A fonte de marca não está aplicada
Hanken Grotesk é importada, mas font-sans e a base não apontam pra ela — e o :root ainda pede "Inter", que nem é carregada. O app renderiza em fonte de sistema.
Crítico
A cor primária do white-label não propaga
bg-primary lê --color-brand-primary (azul fixo), mas o motor grava --brand-primary. São dois namespaces de token que não se falam.
Importante
A escala tipográfica existe, mas é ignorada
Você definiu uma escala completa em @theme, mas os componentes usam tamanhos avulsos como text-[9px], [10px], [11px] — pequenos demais e sem ritmo.
Importante
Cor semântica espalhada e o status usando a marca
Prioridade/SLA são rose/amber/sky hardcoded por componente, sem token. O badge de status usa bg-primary-container — ou seja, muda com a cor do cliente.
01 Tipografia

A escolha está certa — falta ligar na tomada

Hanken Grotesk (texto) + JetBrains Mono (IDs, timers de SLA) é uma ótima dupla para ITSM: neutra, legível em densidade, com mono para números. Este documento inteiro está nessas fontes. O problema é puramente de fiação:

src/index.css · :root
--font-family-display-val: "Inter"; /* não é importada → cai no sistema */
Só os tenants alpha/beta trocam para Hanken Grotesk. Além disso, o utilitário font-sans usado nas telas aponta para o stack padrão do Tailwind, não para a sua fonte. Resultado: a maior parte do app aparece em fonte do sistema, não em Hanken Grotesk.

02 Cor & tokens

O motor white-label existe — mas o fio do "primary" está cortado

O ThemeProvider injeta a cor do cliente em tempo real — mas grava num token que o Tailwind não lê para o bg-primary. Veja o caminho:

Efeito visível: a marca padrão do ServiceFY é emerald #10b981, mas os botões primários saem azuis #2563eb. Trocar a cor do cliente no banco não muda o primary.

Correção: unifique num só namespace. Faça o @theme ler exatamente o token que o motor grava (ex.: --color-primary: var(--brand-primary)), e o mesmo para background.

05 Plano de execução

Ordem sugerida

1
Ligar a fonte de marca CRÍTICO
Em index.css: --font-sans e base = Hanken Grotesk; remover "Inter".
2
Unificar os tokens de marca CRÍTICO
Um só namespace. @theme lê o token que o motor grava (primary + background).
3
Criar tokens semânticos
Arquivo único para prioridade/status/SLA. Tirar PRIORITY_STYLES de dentro da página; status deixa de usar cor de marca.
4
Adotar a escala & validar contraste (AA)
Trocar text-[9/10/11px] pela escala nomeada; garantir contraste dos badges.
